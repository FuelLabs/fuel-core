Support read-only contract inputs (fuel-vm PR #1014): a contract input without the corresponding contract output is now valid and denotes a read-only access to the contract. Its code can be executed and its state and balances read, but the VM panics with `ContractIsReadOnly` on any mutation, so the executor never produces or rewrites an output (state/balance root) for it. This is supported automatically by the new fuel-vm version — there is no consensus parameter or chain-config flag to enable.
