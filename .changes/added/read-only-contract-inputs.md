Support read-only contract inputs (fuel-vm PR #1014): a contract input without the corresponding contract output is now valid when the chain enables the new `TxParameters::V2` `allow_read_only_contract_inputs` consensus parameter. Such an input grants read-only access to the contract — the VM permits executing its code and reading its state and balances but panics with `ContractIsReadOnly` on any mutation — so the executor never produces or rewrites an output (state/balance root) for it. The parameter defaults to off, is opt-in per chain via chain config, and is exposed through the GraphQL API as `TxParameters.allowReadOnlyContractInputs`.
