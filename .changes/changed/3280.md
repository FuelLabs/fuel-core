Move the PoA redis-publish path out of the importer and into the PoA service itself. `BlockReconciliationWritePort` now lives in `fuel_core_poa::ports` and is async; `RedisLeaderLeaseAdapter::publish_produced_block` runs natively on the tokio runtime, fans out to all nodes in parallel via `FuturesUnordered`, reuses cached per-node `MultiplexedConnection`s, wraps each per-node call in `tokio::time::timeout(node_timeout, ...)`, and short-circuits on quorum by dropping the remaining futures. No more rayon bridge, no more `std::thread::spawn` leak from the 2026-04-22 hotfix.

Adds the `poa_quorum_latency_s` metric: a histogram labeled by `operation` (`publish`, `owner_check`, `reconcile_read`, `promote`) recording the wall-clock time-to-quorum of each Redis fan-out. Unlike the per-node `poa_write_block_duration_s` — which hides quorum-completion behind the slowest node — this reports the latency the caller actually waits for.

Removes two ways a single slow Redis node could degrade block production. `acquire_lease_if_free` now distinguishes `LOCK_HELD` from a transport failure and short-circuits the moment a quorum reports the lock held, instead of waiting out every node across all retry attempts — a routine follower lock-check is bounded to one fan-out. And the leader's per-block reconcile is now generation-gated: a freshly promoted leader runs one full all-nodes scan (the only place a sub-quorum orphan must be detected), after which it has held the lock continuously and cannot be behind its own stream, so steady-state cycles use a cheap quorum-gated check. A degraded Redis node no longer adds `node_timeout` to every block — it is re-incorporated by lock expansion and the write fan-out, not by a reconcile scan.

Drops `write_block.lua`'s per-block Redis CPU from O(N) to O(log N). The pigeonhole HEIGHT_EXISTS check no longer scans the stream with `XREVRANGE` (which materializes every entry's payload into Lua memory before iterating); it does a single `ZSCORE` against a new `{lease_key}:heights:index` sorted set populated atomically by the same script. The index is bounded to `2 * stream_max_len + 256` entries via `ZREMRANGEBYRANK` after each successful write, which is strictly larger than the stream's `XTRIM ~` retention so the index always covers what the stream still holds (no false negatives, fork-prevention invariant preserved). Restores headroom on CPU-credit-constrained ElastiCache nodes that were being pushed below baseline by the prior scan.

Stops PoA followers spinning on the leader-state check. `LeaderState::ReconciledFollower` previously did `sleep_until(last_block_created + period)`, but `last_block_created` only advances when the local authority produces a block, so a persistent follower's deadline was always in the past and the loop re-fired `leader_state` on every poll. It now sleeps an explicit `period` so the fan-out happens once per cycle.

Splits the misnamed `poa_promotion_failure_total` counter. The metric now increments only on genuine "retries exhausted without a verdict" failures. The previously-folded-in follower-defer case (quorum reported `LOCK_HELD`) is tracked separately as `poa_promotion_lock_held_total` so dashboards and alerts on the failure counter stop firing on the normal follower happy path.
